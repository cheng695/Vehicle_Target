# Vehicle_Target 项目说明

本文面向首次接手本项目的开发者，介绍项目结构、底盘与云台控制、参数配置、编译和烧录流程。项目目标硬件为 STM32F427 系列，使用 STM32CubeMX 生成的 HAL/FreeRTOS 工程基础，并通过 CMake 和 ARM GNU 工具链构建。

## 1. 项目目录

| 路径 | 用途 |
|---|---|
| `Core/` | STM32CubeMX 生成的启动、HAL、FreeRTOS 与芯片相关代码。 |
| `Drivers/` | CMSIS、STM32 HAL 等底层驱动。 |
| `Middlewares/` | FreeRTOS 等中间件。 |
| `User/Task/` | RTOS 任务及任务间调度，例如遥控输入、控制、CAN 电机和串口通信。 |
| `User/Module/Chassis/` | 底盘控制器、规划器、状态机、事件检测和配置。 |
| `User/Module/Gimbal/` | 云台控制器、Yaw 与升降规划器、状态机、限位处理和配置。 |
| `User/Module/Motor/` | 电机相关控制适配。 |
| `User/core/` | 项目自有的算法、BSP、HAL 抽象和通用组件。 |
| `config/` | 底盘与云台的 YAML 参数源文件。 |
| `tools/` | YAML 转 C++ 头文件脚本、离线配置编辑器及依赖说明。 |
| `cmake/` | ARM 工具链与 STM32CubeMX 子工程的 CMake 配置。 |
| `build.ps1` | 配置并编译 Debug 或 Release 固件。 |
| `download.ps1` | 使用 SEGGER J-Link 将生成的 ELF 固件下载到目标板。 |
| `tests/` | 可独立运行的部分规划器和故障检测逻辑测试源文件。 |

## 2. 软件结构概览

应用主要分为任务层、控制模块和硬件抽象层：

1. `User/Task/` 负责周期调度以及遥控、CAN、UART 等输入输出。
2. `User/Module/RobotContext.*` 集中声明跨任务共享的电机、输入、目标和输出对象。
3. 底盘和云台控制器读取输入，调用各自规划器、状态机和检测器，生成电机控制输出。
4. `User/core/` 中的 HAL/BSP 组件负责与 STM32 外设及电机、遥控器接口交互。

`ControlTask` 当前以约 1 ms 周期运行底盘和云台控制；`MotorTask` 周期发送 CAN 电机命令；遥控输入由串口接收任务解析。实际周期仍应以任务代码和 RTOS 配置为准，修改依赖周期的参数时要同步确认调用周期。

### 底盘模块

底盘使用四轮全向运动学。`ChassisController` 组合逆运动学、车轮速度 PID、状态机、事件检测器和规划器。规划器处理遥控目标和自动往返目标；车轮速度反馈用于正运动学反馈及闭环控制。

### 云台模块

云台控制分为 Yaw 旋转轴和升降机构（代码中使用 `hight` 命名）。Yaw 支持停止、匀速和变速目标规划；升降控制包含速度规划、PID、上下限位和位置基准。堵转检测参数已配置，但目前检测器的周期更新调用处于禁用状态，不能视为正在生效的保护功能。

DT7 两个三档拨杆与滚轮的具体行为见[底盘与云台控制模式说明](../ChassisGimbalControlModes.md)。

## 3. 参数配置和调试

参数配置、离线网页和 Ozone 调参的详细步骤见[配置与调参](配置与调参.md)。以下为流程摘要。

### YAML 配置与生成头文件

可长期保存的底盘和云台参数分别维护在：

- `config/chassis.yaml`
- `config/gimbal.yaml`

构建时 CMake 调用 `tools/generate_chassis_config.py` 和 `tools/generate_gimbal_config.py`，生成：

- `User/Module/Chassis/ChassisConfig.hpp`
- `User/Module/Gimbal/GimbalConfig.hpp`

应修改 YAML 源文件，不要把生成的 `.hpp` 当作参数源直接编辑；下一次生成会覆盖头文件。修改 YAML 后重新构建并烧录，新的值才会成为固件默认值。

安装 YAML 生成依赖：

```powershell
python -m pip install -r tools/requirements.txt
```

也可以在项目根目录手动生成头文件：

```powershell
python tools/generate_chassis_config.py
python tools/generate_gimbal_config.py
```

### 离线配置编辑器

配置编辑器在本机启动，不连接机器人：

```powershell
python tools/chassis_config_editor.py
```

浏览器访问 `http://127.0.0.1:8765`。首页包含底盘配置、云台配置和挡位说明。编辑后可以保存到项目 YAML 或导出 YAML；保存后仍需重新构建和烧录，参数才会进入固件。

### Ozone 在线调参

控制环运行期间可调的变量位于 RAM 中的 `volatile` 变量：

- 底盘：`ChassisTuning`，定义在 `User/Module/Chassis/ChassisTuning.hpp/.cpp`。
- 云台：`GimbalTuning`，定义在 `User/Module/Gimbal/GimbalTuning.hpp/.cpp`。

在 Ozone 的 Watch 窗口可以查看和修改，例如：

```text
ChassisTuning::WHEEL_PID_KP[0]
ChassisTuning::REMOTE_LINEAR_GAIN
GimbalTuning::HIGHT_PID_KP
GimbalTuning::HIGHT_GRAVITY_FEEDFORWARD
```

具体可调项以对应的 `*Tuning.hpp` 声明及控制代码实际读取情况为准。在线修改只在本次上电/调试期间生效，复位或断电后恢复为 YAML 生成的默认值。确认合适参数后，应把最终数值写回 YAML，再构建固件以保存为默认配置。Ozone 调试建议使用 Debug 构建。

硬件 ID、轮数、车轮布局、减速比、GPIO 限位有效电平等配置属于硬件或编译期配置，不应当作普通闭环调参项随意修改。

## 4. 新电脑环境准备

Windows 开发机需要准备：

- CMake 3.22 或更新版本。
- Ninja。
- ARM GNU Toolchain，确保 `arm-none-eabi-gcc`、`arm-none-eabi-g++`、`objcopy` 和 `size` 可从 `PATH` 找到。
- Python 3.8 或更新版本和 PyYAML，安装方式见上文。
- 下载固件时还需要 SEGGER J-Link Software、兼容的 J-Link 调试器和目标板。
- PowerShell 可执行 `.ps1` 脚本；如果系统执行策略阻止脚本，可在当前用户环境中按组织策略处理执行策略。

项目使用相对路径定位源码和构建目录，换电脑后应从仓库源码重新配置构建；不要复制另一台电脑的 `build/` 目录作为新机器的构建环境。

## 5. 构建固件

在项目根目录打开 PowerShell：

```powershell
./build.ps1
```

默认构建 Debug。Release 构建：

```powershell
./build.ps1 -Config Release
```

清理所选构建配置后重新编译：

```powershell
./build.ps1 -Config Debug -Clean
```

脚本调用 CMake Presets 和 Ninja。构建产物位于 `build/Debug/` 或 `build/Release/`，主要文件包括：

- `Vehicle_Target.elf`：带调试信息的 ELF 文件，也供下载脚本使用。
- `Vehicle_Target.hex`：Intel HEX 固件文件。
- `Vehicle_Target.bin`：二进制固件文件。

## 6. 烧录固件

先成功构建，再确认目标板和 J-Link 已连接。在项目根目录执行：

```powershell
./download.ps1
```

默认下载 `build/Debug/Vehicle_Target.elf`，设备型号参数为 `STM32F427II`，接口为 SWD，速度为 4000 kHz。可按实际硬件覆盖参数：

```powershell
./download.ps1 -Config Release -Device STM32F427II -Interface SWD -Speed 4000
```

如果找不到 `JLink.exe`，将 J-Link 安装目录加入 `PATH`，或使用脚本支持的 SEGGER 默认安装路径。下载前确认目标芯片型号、调试接口和接线正确。

## 7. 常见问题

| 现象 | 检查方向 |
|---|---|
| CMake 报版本或命令不存在 | 安装 CMake 3.22+ 并检查 `PATH`。 |
| Ninja 或 ARM 编译器未找到 | 安装 Ninja、ARM GNU Toolchain，并把可执行文件所在目录加入 `PATH`。 |
| CMake 提示缺少 Python/YAML | 安装 Python 3.8+，然后执行 `python -m pip install -r tools/requirements.txt`。 |
| 配置头文件没有更新 | 检查编辑的是 `config/*.yaml`，然后重新运行构建或手动生成脚本。 |
| 烧录提示找不到固件 | 先用相同的 `-Config` 参数运行 `build.ps1`。 |
| 烧录提示找不到 J-Link | 安装 SEGGER J-Link Software，检查 `JLink.exe` 是否在 `PATH` 或常见安装目录。 |
| Ozone 中找不到调参符号 | 确认使用 Debug ELF，并在 Ozone 加载当前构建的 `Vehicle_Target.elf`。 |
